# 观感：对着原版截图验

目标是看起来和原版同一路：版式、信息层级、间距、字号层次、深浅色表现。像，但自己写：不用原 App 的主题文件、样式代码、字体、图标、文案（需求表的边界照旧），不从截图里抠图、取色照抄。截哪些界面、怎么比，由 Agent 定，不问人。

## 第 2.5 步做 L1 时：截原版

1. 写或挑一份典型示例文档，原版和成品都用它；第 4 步放进 `tests/corpus/`。
2. 定 3–5 个界面状态，写成 `states.md`：

| # | 状态 | 怎么到达 | 原版截图 |
| --- | --- | --- | --- |
| S1 | 打开示例文档 | 打开 `<文件>` | `orig-s1-document.png` |
| S2 | 刚启动，没打开文件 | 启动 | `orig-s2-start.png` |
| S3 | 正在编辑 | 光标放在 `<位置>`，输入 `<内容>` | `orig-s3-editing.png` |
| S4 | 主要的菜单、对话框或设置页 | `<操作>` | `orig-s4-dialog.png` |
| S5 | 出错或冲突的提示 | `<操作，如打开超限文件>` | `orig-s5-error.png` |

3. 原版窗口调到 1280×900，浅色截一套；原版支持深色的，S1 再截一张深色（`orig-s1-document-dark.png`）。桌面 App 用 kimi-cu 截窗口，网页用 Playwright。
4. `states.md` 里给每个状态写上界面本体的尺寸（pt，去掉阴影和透明边），注明截图是视网膜 2x。不然实现方会自己换算：Typeless 那次 800×488 pt 的窗口被当成像素又除了 2，答案卡只做到原版一半大。浮层类 App（菜单栏、悬浮条）截的是透明面板，本体只占一角，更要写清。
5. 先存 `~/labs/<代号>/evidence/ui-target/`；第 4 步连同 `states.md` 拷进新仓库 `tests/locked/ui-target/`，跟锁定测试一起算哈希。

## 夜里：打磨阶段自己对照

- 按 `states.md` 截当前构建（同样 1280×900、同一份示例文档），和对应的原版截图对照（能看图就自己看），挑差得最大的一处改，改完重截。
- 只对齐版式、层级、间距、字号层次和深浅色表现，不照抄主题、字体、图标、文案。原版截图不进产品、README 和安装包。
- 记在 `docs/ui-review-log.md`：状态、和原版差在哪、改了什么、谁评的（模型名，自评）、提交号。

## 晨检：逐张对照

1. 按 `states.md` 用当前构建重截，存 `~/labs/<代号>/audit/ui/`。
2. 视觉模型逐张和原版截图比，每张给两样：
   - 和原版的一致程度：高 / 中 / 低，一句话说差在哪（版式、层级、间距、字号层次、深浅色）。
   - 缺陷清单：溢出、错位、对比度不够、深色模式坏掉，有一项写一项；照抄了原版的图标、文案、字体，也算缺陷。
3. 报告里原版和当前截图并排放（左原版、右当前），让用户看一眼就能判断。可以用 Playwright 把两张拼成一张 `side-by-side-<状态>.png`。
4. 写明谁评的（哪个模型，或人）。夜里的自评只作参考，不照抄。
