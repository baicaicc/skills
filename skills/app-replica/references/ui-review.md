# 观感：选样稿，对着样稿验

用户只看样稿选一张；截哪些界面、怎么比，由 Agent 定，不问人。

## 睡前：做样稿（第 4 步，约 15 分钟）

1. 从 `tests/corpus/` 挑一份典型文档当示例，所有样稿都用它。
2. 做 2–3 个主窗口的静态 HTML 样稿，风格明显不同：版式、字体与行宽、配色至少两样不一样（如极简留白 / 带侧栏和工具栏 / 深色为主）。
3. 边界同需求表：不用原 App 的主题、图标、字体、文案；字体用系统字体或许可兼容的开源字体。每张样稿是一个自包含的 HTML 文件（CSS 内联，不引外网资源）。
4. 用 Playwright 按 1280×900 截图：`sample-a.png`、`sample-b.png`……App 要支持深色的，样稿写好 `prefers-color-scheme: dark`，另截 `sample-a-dark.png` 等。
5. 放进确认卡「外观选哪个」：每张一句话说风格，标一个推荐（用户只回「行」就用它）。
6. 定好晨检要对照的界面状态，写成 `states.md`（3–5 个）：

| # | 状态 | 怎么到达 | 截图文件 |
| --- | --- | --- | --- |
| S1 | 打开示例文档（和样稿同一份） | 打开 `<文件>` | `s1-document.png` |
| S2 | 刚启动，没打开文件 | 启动 | `s2-start.png` |
| S3 | 正在编辑 | 光标放在 `<位置>`，输入 `<内容>` | `s3-editing.png` |
| S4 | 主要的菜单、对话框或设置页 | `<操作>` | `s4-dialog.png` |
| S5 | 出错或冲突的提示 | `<操作，如打开超限文件>` | `s5-error.png` |

S1 和样稿是同一份内容，直接比；其余状态样稿里没有，比风格是否一致。

## 用户回复后：锁定

- 选中的那张拷进 `tests/locked/ui-target/`，改名 `target.html`、`target.png`（有深色的再加 `target-dark.png`），连同 `states.md`，跟锁定测试一起算哈希。
- 没选中的留在 `~/labs/<代号>/plan/ui-samples/`，不进仓库。

## 夜里：打磨阶段自己对照

- 照样稿的版式、字体、配色和间距做，不求像素一致。
- 按 `states.md` 截当前构建，和 `target.png` 对照（能看图就自己看），挑差得最大的一处改，改完重截。
- 记在 `docs/ui-review-log.md`：状态、和样稿差在哪、改了什么、谁评的（模型名，自评）、提交号。

## 晨检：逐张对照

1. 按 `states.md` 用当前构建重截，存 `~/labs/<代号>/audit/ui/`。
2. 视觉模型逐张和样稿比，每张给两样：
   - 和样稿的一致程度：高 / 中 / 低，一句话说差在哪（S2–S5 比风格是否一致）。
   - 缺陷清单：溢出、错位、对比度不够、深色模式坏掉，有一项写一项。
3. 报告里样稿和当前截图并排放（左样稿、右当前），让用户看一眼就能判断喜不喜欢。可以用 Playwright 把两张拼成一张 `side-by-side-<状态>.png`。
4. 写明谁评的（哪个模型，或人）。夜里的自评只作参考，不照抄。
